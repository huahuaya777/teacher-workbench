# ChatGPT 会员额度接入核对

更新日期：2026-10-16。**状态：官方文档已核对，项目资格与实际接入待验证；本文件是设计记录，不表示功能已实现。**

## 已确认需求

- 用户希望尽量利用现有 ChatGPT Plus 额度，避免为了最小验证版先充值 API。
- 工作台供 2～5 人分别使用，资料、对话及模型配置默认私有。用户希望配偶在她自己的工作台账号中使用其现有 Plus 授权，但这种跨人使用方式尚未获得官方确认。
- 不收集会员密码、Cookie、Codex 凭据或手工复制的 OAuth token；不建立订阅转发。真实模型请求必须由使用者主动触发。

## 官方文档核对结果

1. [Sign in with ChatGPT 快速入门](https://developers.openai.com/siwc/quickstart)：合资格 Plus／Pro 用户可以在获准应用中授权使用本人计划额度；开放源码客户端可以不提供普通 API Key。官方同时写明：计划使用目前面向所有开放源码合作方和部分获准的私有客户端。登录身份权限与模型调用权限分开，后者需要单独授权。
2. [计划使用概览](https://developers.openai.com/siwc/token-sharing-open-source)：该流程说明针对开放源码及本地托管应用；对付费或远程托管应用提供意向申请入口。私有仓库、家中 Ubuntu 虚拟机、多个教师账号的组合是否符合当前条件，文档没有直接给出本项目的资格结论。
3. [账号与会话](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)：不同 ChatGPT 账号的注册和令牌必须分开，不能混用。Plus 的五小时使用额度在使用其计划的应用之间共享，并非每个应用另有一份。
4. [模型调用与预览限制](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)：获准用户的 OAuth 令牌用于公开 `POST /v1/responses`，请求须 `store: false`、`stream: true` 并完整处理流式结束事件；不能调用 ChatGPT 内部接口。当前工作台代码使用 API Key 和 `/chat/completions`，不能把会员登录信息直接填入现有配置。
5. [自托管虚拟机说明](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)：官方说明了获准开放源码应用在自托管 VM 上使用稳定主机标识和受保护凭据的流程；该说明不等于本项目已获准，也不授权把一个人的凭据借给另一位教师使用。
6. [官方 Cookbook](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)进一步区分开放源码、本机运行的个人项目和获准的私有应用，并要求付费或远程托管应用先申请资格。[申请入口说明](https://developers.openai.com/siwc/request-client-id)提供官方意向表入口。当前项目计划在家中服务器为数人提供浏览器访问，不能把“个人电脑本机运行”的条件直接套用到它。

## 当前项目核对

- **代码已写／本机测试通过：** 千问等普通 API 的 Chat Completions 适配器只通过假接口测试；真实 AI 默认关闭。它不是 ChatGPT 会员授权适配器。
- **待验证假设：** 当前私有多人工作台能否申请或获得计划使用资格；具体可用账号和模型；配偶能否以独立工作台身份使用用户的 Plus 计划；家中服务所需回调、令牌保护、撤销与恢复流程。
- **禁止据此宣称：** “已连接 ChatGPT Plus”“会员额度可共享给家人”“不需要任何用量限制”或“不会产生任何费用”。

## 如获得官方资格后的阶段 1 接入设计

1. 每位实际授权者本人在 OpenAI 官方页面完成登录与授权；工作台账号与经过验证的 ChatGPT 账号身份一对一绑定。不同人的令牌、资料、任务和额度记录分开。跨人代用需先有明确官方依据，不能由应用自行放宽。
2. 令牌仅存受保护的服务端运行环境，静态加密及密钥恢复方案先设计并验收；不写入浏览器存储、日志、Git 或教学文档。支持断开授权与令牌撤销。
3. 单独实现符合官方合同的 Responses API 流式适配器，继续沿用现有结构化作业草稿校验、版本保存、预览和 Word 导出；无可用授权时明确报错，不自动切换千问 API。
4. 用虚构资料做一次由实际授权者主动触发的最小调用；验证身份绑定、可用模型、用量提示、错误处理、撤销后不能再请求，再由用户验收 WPS 结果。不能凭离线单元测试宣布会员接入成功。

## 当前结论与下一步闸门

目前只能确认官方**存在**条件性途径，无法从公开文档确认本项目或跨人使用已获准。2026-10-16 用户查看[官方申请入口说明](https://developers.openai.com/siwc/request-client-id)，反馈页面提示目前仅向部分商业合作伙伴开放，其他申请需填写意向表。这是等候名单，不能据此承诺本项目近期获准。会员适配器保持未启用，不进行 OAuth 注册、令牌转移或真实调用；意向表可作为平行申请，不能阻塞阶段 1 最小验证版。现先沿用已实现的千问 API 接口准备本地验证。获准后仍需每位实际使用的 ChatGPT 账号所有者本人授权；不要发送密码、令牌或支付信息。
