# 技术方案——方向已确认

**状态：用户于 2026-10-14 确认技术方向；Ubuntu 隔离预发布栈已有虚构样例现场测试，正式环境尚未部署。** 本方案围绕 2～5 人、单台 2 vCPU/4GB Ubuntu 主机、初学者维护和 Docker 部署设计。功能目标来自 [requirements.md](requirements.md)；服务器参数及后续测试结果见[环境记录](environment.md)。阶段 2 成员账号和密钥方案见[独立设计](phase2-accounts-and-keys.md)；正式环境的资源、恢复与 WPS 兼容性仍需按场景实测。

## 建议结构

- **应用：Python + Django 单体 Web 应用**。先用服务端页面与少量渐进式交互实现电脑及手机界面，避免第一版同时维护独立前端、后端两套工程。Django 提供成熟的用户、会话与权限基础；实际“默认私有”和跨用户隔离仍须逐接口设计和测试。Django 官方说明其认证和权限系统可扩展，且默认认证不自带暴力破解限速，因此上线前还须加登录限速。参见 [Django 认证文档](https://docs.djangoproject.com/en/5.2/topics/auth/customizing/)。
- **数据库：PostgreSQL**。存账号、教学档案、资料元数据、任务、草稿版本、额度与审计所需记录；上传原文件和导出文件放在服务器受控文件目录，不把大文件塞进数据库。每条私有记录绑定所有者，共享关系单独记录；管理员操作不自动获得私有内容读取权。具体表结构待阶段 1 设计。
- **后台任务：独立 worker 与队列**。AI 生成、文档转换、导出等耗时任务从网页请求中分离；拟用 Redis 作为队列基础，具体 Python 任务库待原型验证。排队、取消、重试、费用统计与任务状态要在调用前后留下明确记录。4GB 内存下先限制并发，实测后再定值。
- **文档流水线：保留原文件、抽取可处理内容、生成结构化草稿、预览、导出 DOCX**。学生卷和教师版从同一份已确认草稿生成，减少预览与导出内容偏差；公式优先尝试导出为可编辑的 Word 数学对象，具体转换库和 WPS 效果必须通过样本验证，不能仅凭 DOCX 格式保证。图形质量和答案仍需教师检查。
- **PWA：响应式网页、manifest 与必要的 service worker**。优先保障在线使用和手机四项核心操作；离线能力不是当前承诺。MDN 指出可安装 PWA 需 manifest，并在 HTTPS 或本机开发地址提供应用，见 [MDN 安装条件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。
- **部署：Docker Compose 管理 Web、worker、PostgreSQL、Redis**，正式环境另配可信 HTTPS 入口，并通过现有 EasyTier 子网代理供已加入的外部设备访问。EasyTier 位于 PVE LXC 140，工作台仍在 Ubuntu VM 257；不修改现有组网。入口和证书方案见 [网络访问计划](network-access-plan.md)。Compose 适合在单机定义和管理多服务，见 [Docker Compose 官方文档](https://docs.docker.com/compose)。开发测试与正式环境使用不同配置、数据库、文件目录和密钥；发布前走测试、用户确认、备份、发布、验证流程。
- **备份：数据库一致性备份 + 上传/导出文件 + 必需的恢复密钥**，定时复制到现有 OMV NAS，保留多版本并定期在测试环境恢复。目录、加密、保留周期、恢复时间目标均待用户确认；仅看到备份文件不算验收通过。

## 为什么这样取舍

- 单体 Django 能减少初期部署和维护面，但交互很复杂时可能需要更多前端代码；先依据最小流程验证，不提前引入完整前后端分离。
- PostgreSQL 比单文件数据库多一个容器，却更适合多人并发、权限关联和可靠备份；对于正式主资料库更稳妥。
- 任务队列增加 Redis 和 worker 两个运行单元，但 AI 与文档处理可能较慢，需要排队、进度与取消；在最小版先实现必要状态，费用控制按真实接口能力逐步验收。
- 上传文件保留在私有目录便于备份与下载；同时必须防止任意用户直接访问文件 URL，下载须经过权限检查。
- 不在本地服务器运行大型模型，先让用户主动配置可用接口；可选供应商、费用和 Plus 账号的授权资格均待确认。

## 关键边界和待确认项

1. **AI 接口**：厂商、模型、图像与工具能力、价格、额度、安全保存 API Key 的方式；不自动调用付费模型。现有 Plus 账号用于工作台的官方资格与可行性未确认，不以其为依赖。
2. **文件兼容**：Word/PDF/PPTX/图片的解析策略；希沃专用文件第一版只保证按权限保存与下载，解析待验证。DOCX 公式可编辑与 WPS 打印效果需样本验收。
3. **网络安全**：EasyTier 产品已确认；客户端实际路由、专用域名、HTTPS 证书、反向代理入口、登录限速及上传大小限制待核对。不能因已能访问家庭网段或 Docker `hello-world` 成功就推断工作台可从外部安全访问。
4. **容量和备份**：实际剩余磁盘、4GB 内存下的并发、NAS 路径与恢复演练待验证。
5. **界面**：已认可首页文件已于 2026-10-15 导入 [设计参考](../design-reference/README.md)；当前 Django 页面已采用柔和绿色三栏与手机独立 AI 视图。电脑端导航获用户认可，手机窄屏已在本机 Chrome 检查，真机待验收；原型中的演示数据不能直接当正式记录。
