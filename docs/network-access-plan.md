## 已核对的技术边界

- EasyTier 的 `-n` 用于把本地子网通告给同一虚拟网络的客户端；它负责网络可达性。参见 [EasyTier 子网代理文档](https://www.easytier.cn/guide/network/point-to-networking.html)。用户给出的 Compose 没有工作台网页的 TLS/证书设置，因此不能据此认定 `http://10.0.30.5` 是可信 HTTPS。
- 浏览器的可安装 PWA 需要 HTTPS（本机 `localhost`/`127.0.0.1` 开发地址例外）。远程设备通过 EasyTier 打开私网 IP 的普通 HTTP 不满足该条件，见 [MDN PWA 安装条件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。
- 当前最小版继续做浏览器功能和私网路径验证；**不把 HTTP 私网访问记为 PWA 已实现，也不把现有 `DEBUG=1` 测试站开放到家庭网段**。

## 后续：可信 HTTPS 与 PWA（当前不执行）

- 若以后恢复可安装 PWA 目标，再选择域名与证书方案；域名不一定要经过 Cloudflare 代理。DNS-01 能为仅在私网可达的域名签发证书，见 [Let's Encrypt 说明](https://letsencrypt.org/docs/challenge-types/)，但签发、续期、客户端解析都需实测。

## 目前不能下结论的事项

- LXC 140 当前容器版本、在线状态、每台外部设备的路由；目前只有一台 Windows 设备的 SSH 端口 TCP 结果，工作台端口尚未提供直接远程服务。
- Ubuntu 防火墙对其他端口的行为、独立预发布入口、新版登录限速与当前账号的跨账号浏览器访问。SSH 本地转发的旧测试站登录、首页、虚构资料上传列表和下载打开已有用户反馈；域名、Cloudflare 记录、证书和自动续期属于后续 PWA 阶段，当前不要求用户核对。
- EasyTier 成员可达的其他网段较广；PVE/其他服务的实际访问控制由现有网络和防火墙决定，不能仅凭子网代理条目断言均可登录。教师工作台自身仍须独立账号和权限验证。
