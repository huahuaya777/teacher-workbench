## 已有证据

- **用户实际验收通过（范围有限）：**虚构数学资料的两版作业、学生卷与教师答案版 Word，用户已在 WPS 核对简单公式可编辑、三题答案、排版及打印预览。纸张实际打印、复杂题目与真实教学资料未验收。
- **用户现场技术测试通过：**Ubuntu 隔离测试栈的 PostgreSQL 虚构资料流程、默认私有与跨账号拒绝；一份数据库和私有文件配对备份已转存到专用 NAS，并从 NAS 副本恢复到独立新卷。原测试站仍返回 HTTP 200。以上来自用户提供的终端输出，助手没有直接登录服务器。
- **用户现场技术测试通过（2026-10-16）：**新版 PostgreSQL 完整回归输出 `OK (skipped=11)`、测试数据库销毁、`POSTGRES_REGRESSION_SUITE_OK` 和 `SOURCE_TEST_LOGIN_HTTP_200_AFTER_REGRESSION`。按已核对的脚本，只有一次性 Web 容器内测试命令成功才会打印完整回归标记；既有测试站随后仍返回 HTTP 200。用户提供的是输出末尾，未包含 `Ran ... tests` 行，故不记录现场发现的具体测试总数。
- **用户实际浏览器验收通过（2026-10-17，范围有限）：**家外 Windows 经 EasyTier 到 Ubuntu SSH 端口的 TCP 测试返回 `True`；用户通过 SSH 本地转发在既有测试站看到登录页，用单独创建的虚构普通账号进入首页，并反馈虚构 Word 出现在“我的资料”，下载的 Word 能打开。未核对下载哈希、服务器提取字段、第二账号浏览器访问、手机或正式环境。当前 Web/worker 仍是旧代码，不能把这次登录算作新版限速验收。
- **代码已写、本机测试通过：**全量回归测试现在把 11 项只适用于本机 SQLite 的命令/排队测试标为 PostgreSQL 跳过；新增 3 项仅在 PostgreSQL 配置运行的命令防护测试。模拟模型的两项业务测试显式使用假的 OpenAI 兼容配置，避免继承 Ubuntu `.env` 中的千问厂商设置。工作流测试改用 `TransactionTestCase`，避免关闭流式 Word 响应后沿用外层长事务里的数据库连接。未放宽真实命令的 SQLite 安全闸门。以 `AI_PROVIDER=qwen`、AI 关闭的本机 SQLite 环境运行 38 项，35 项通过、3 项 PostgreSQL 专用测试跳过；模拟 PostgreSQL 设置、无数据库连接时单独运行 3 项命令防护测试也通过。无真实模型请求。

## PostgreSQL 回归测试复核

2026-10-16 旧版 35 项测试在 Ubuntu 有 5 项失败、16 项报错。已从用户提供的完整日志确认：本机专用命令和队列测试误在 PostgreSQL 执行；模拟 AI 测试受厂商环境设置影响；后段还出现 PostgreSQL 连接关闭。流式 Word 响应关闭与 `TestCase` 外层事务的相互影响是当时的**代码分析假设**；新版测试在 PostgreSQL 整套通过，仍无法单独证明该假设就是唯一原因。

本机发现 38 项测试。已准备并由用户在 Ubuntu 257 运行 [单次回归脚本](../scripts/verify_ubuntu_postgres_regression.sh)：先核对脚本和测试文件哈希、回环绑定、四服务及测试数据库不存在；再起一次性 Web 容器，只读挂载新版 `tests.py`，在**临时 PostgreSQL 测试数据库**中运行回归。运行中的 Web/worker、既有镜像和业务卷不更新。用户现场输出表明整套测试成功、11 项跳过、测试数据库已销毁、原测试站仍返回 HTTP 200。未据此验收真实资料或正式服务。

## 当前结论

最小验证版的**虚构样本链路**已有用户 WPS、服务器技术及临时隧道浏览器证据；新版 PostgreSQL 完整回归、NAS 来源数据恢复及依赖本机配对旧镜像的渲染代码重建也有用户现场成功标记。发布前的运行安全、实际资料、HTTPS/PWA、自动备份与凭据恢复等缺口仍在上节。当前不部署正式服务，不把测试栈直接开放到 EasyTier 网络。后续先以独立设计和小步测试推进阶段 2 账号与密钥管理，不能把本次限定验收当成完整第一版发布批准。
